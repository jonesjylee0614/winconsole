````markdown
# WinConsole Manager – 展示与提示优化方案

## 1. 总体思路

在现有架构（左侧会话列表 + 右侧终端）的基础上增加两层东西：

1. **信息展示层（Header + 会话卡片）**  
   把“当前会话是什么、在干嘛、路径在哪、跑的是什么命令”清楚地摆出来。
2. **提示与引导层（Hints / Actions）**  
   给每个会话配置「常用操作提示」，在 UI 里用固定区域展示下一步建议，让界面不再是“黑盒”。

目标：打开工具时，你一眼就知道：

- 当前有哪些会话；
- 每个会话在干什么；
- 换到一个会话后，下一步可以执行什么命令。

---

## 2. 布局优化方案

### 2.1 主界面分区

右侧区域从“只放终端”改为三块：

```text
┌───────────────────────────────────────────────┐
│ 顶部：会话头部栏 Session Header               │
│  - 名称 / 状态 / Shell / 路径 / 标签 / 描述   │
├───────────────────────────────────────────────┤
│ 中间：终端 TerminalWidget                     │
├───────────────────────────────────────────────┤
│ 底部：提示栏 Hint & Actions                   │
│  - 常用命令按钮 / 快捷键说明 / 模板提示       │
└───────────────────────────────────────────────┘
````

#### 2.1.1 会话头部栏（Session Header）

增加一个横向栏（`QWidget + QHBoxLayout`），放在终端上方，显示当前会话关键信息：

* 会话名：`[evoice-gpu (wsl)]`
* 状态：● 运行中 / ○ 已退出 / ✕ 错误
* Shell 类型：`PowerShell / CMD / WSL / Bash`
* 当前工作目录：`/mnt/d/WorkSpace/code/2025/FunASR`
* 标签：`[asr] [demo] [gpu]`
* 描述：`FunASR html5 demo 标点问题排查`

实现要点：

* 当切换 Session 或收到 `SessionManager.on_session_updated` 时刷新这条栏。
* 描述字段允许在 UI 里编辑（右上有一个「编辑描述」的小按钮），修改后写回 `Session.description`。

#### 2.1.2 底部提示栏（Hint & Actions Bar）

在终端下方加一个横条（`QWidget + QHBoxLayout`），用于展示“下一步可以干什么”：

* 左侧：几条文字提示（来自模板配置）
* 右侧：几个按钮（常用命令）

示例：

```text
提示：
- 常用命令：ls / git status / pytest
- F5：运行 demo 脚本   F6：重启服务

[运行 demo] [查看日志] [打开项目目录]
```

UI 上可以这样做：

* 文本用 `QLabel`，前面加一个小图标（灯泡 💡 可以换成其他符号）。
* 按钮用 `QPushButton`，点击后自动在终端中输入对应命令并回车。

## 3. 配置层增加「描述 + 提示 + 常用动作」

在 `sessions.yaml` 里给每个模板加几个字段，专门为 UI 服务：

```yaml
- id: funasr-demo
  name: "FunASR demo"
  cmd: "wsl.exe"
  args:
    - "-d"
    - "Ubuntu-22.04"
    - "--"
    - "bash"
    - "-lc"
    - "cd /mnt/d/WorkSpace/code/2025/FunASR && python demo.py"
  cwd: "D:/WorkSpace/code/2025/FunASR"
  tags: ["asr", "demo"]
  description: "调试 FunASR runtime/html5，重点看中文标点输出。"
  hints:
    - "1. 先运行 demo，确认是否有标点。"
    - "2. 若无标点，检查前端 js 是否对结果做了裁剪。"
    - "3. 可打开浏览器 devtools 查看接口返回原始 JSON。"
  actions:
    - label: "运行 demo"
      command: "python demo.py"
    - label: "查看日志"
      command: "tail -n 100 logs/app.log"
    - label: "列出 html5 目录"
      command: "ls runtime/html5"
```

对应 `SessionTemplate` 增加字段：

```python
@dataclass
class SessionTemplate:
    id: str
    name: str
    cmd: str
    args: List[str]
    cwd: str
    tags: List[str] = field(default_factory=list)
    env: Dict[str, str] = field(default_factory=dict)
    description: str = ""
    hints: List[str] = field(default_factory=list)
    actions: List[Dict[str, str]] = field(default_factory=list)
```

`Session` 也带上 `description`（可以在运行期修改）。

`config_loader.py` 里读取这些字段，UI 的：

* 头部栏显示 `description`；
* 底部提示栏显示 `hints` + 做成按钮的 `actions`。

## 4. 左侧会话列表的展示优化

现在你觉得「展示有问题」，通常是因为左侧只是一个纯文本列表。可以做两步优化：

### 4.1 用「卡片式」信息，而不仅是名字

ListItem 上显示多行信息：

* 第一行：会话名 + 状态点
* 第二行：`cwd` 的末尾目录名，如 `.../FunASR`
* 第三行：标签汇总，如 `[asr] [demo]`

通过 `QListWidget.setItemWidget` 自定义 item 的小 widget，比如：

```text
[evoice-gpu (运行中)]
/mnt/d/.../evoice/nevoice
[ evoice ][ gpu ][ dev ]
```

这样光看左侧就知道每个会话对应哪块工程。

### 4.2 支持按标签过滤 / 搜索

顶部加一个搜索框 + Tag 下拉：

* 搜索：按名称 / 描述 / cwd 模糊匹配；
* Tag 过滤：只显示带某个 tag 的会话（比如只看 evoice 相关）。

实现上很简单：自己维护一份完整 session 列表，根据过滤条件刷新 QListWidget 即可。

## 5. 提示系统（不打扰但随时可见）

除了每个会话自己的提示，还可以加一个全局帮助入口，解决你说的“提示也没有”。

### 5.1 全局快捷键提示

* 工具栏加一个 `?` 按钮，或菜单 `帮助 -> 快捷键`；
* 弹出一个小的 `QDialog`，列出常用快捷键：

例如：

```text
Ctrl+N    新建会话
Ctrl+W    停止当前会话
Ctrl+Tab  切换到下一个会话
Ctrl+Shift+F 在当前终端输出中搜索
F5        执行当前会话模板的默认动作
```

### 5.2 空状态提示（Empty State）

当：

* 没有任何会话时，右侧区域不要全黑，可以显示：

```text
还没有任何会话。

你可以：
- 从模板新建一个会话（点击左上角“新建会话”）
- 或者导入你的 sessions.yaml 模板。
```

* 当前会话终止时，在终端底部提示几条「下一步动作」，比如：

```text
[进程已退出] 你可以：
- 重新运行 demo
- 打开日志检查错误
- 修改描述记录本次调试结果
```

## 6. 与你当前工作流的映射

以你现在调 FunASR 为例：

* 左侧一眼就能看见：

  * `FunASR demo` 会话在 `/FunASR`；
  * `evoice-gpu` 会话在 `/evoice/nevoice`；
* 切到 `FunASR demo`：

  * 头部栏看到：
    `调试 FunASR runtime/html5，重点看中文标点输出。`
  * 底部提示栏看到：
    -「先运行 demo，确认是否有标点」
    -「如果没有，检查前端 js 是否裁剪」
  * 右侧按钮：`[运行 demo] [查看日志] [列出 html5 目录]`，点一下就输入命令。

这时候「展示」和「提示」都变成结构化、稳定的，而不是现在那种“纯终端 + 自己记”。

## 7. 实现优先级建议

先做最便宜、收益最高的几步：

1. SessionTemplate 加上 `description / hints / actions`；
2. 右侧顶部增加 Session Header，至少显示：

   * 名称 / 状态 / cwd / 描述；
3. 底部加一个简单的 Hint 区域：

   * 把模板里的 `hints` 逐行列出来；
   * 再把 `actions` 渲染成按钮，点击后向当前 TerminalBackend 写入命令并回车；
4. 左侧列表 item 显示两行：`名称` + `cwd 最后一级目录`。

这些做完，你的整体体验会立刻从“裸终端”变成“有上下文、有引导的工作台”，不需要改 PowerShell，也不会把自己拖进 GUI 深坑。
